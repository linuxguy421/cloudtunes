# Control-plane onboarding

## Public account registration

Public self-registration is enabled by default in the primary Compose deployment. Open `/register` in a browser or use the Register link on the sign-in page.

The registration form accepts a display name, email address, password, and password confirmation. Email addresses are trimmed and normalized to lowercase. Passwords must be at least 12 characters and confirmed. The form is CSRF-protected and rate-limited.

New accounts are created as regular users with `approval_status=pending`. Registration does not sign the user in and does not grant administrator privileges. Pending users cannot create stations until approved.

To disable public registration, set `CLOUDTUNES_PUBLIC_REGISTRATION_ENABLED=false` in the Compose `.env` file and recreate the control-plane services. The registration page and submission endpoint then return 404.

## Initial administrator

1. Register the intended administrator through the public `/register` page.
2. Promote that existing account from the primary control-plane container:

```sh
docker compose exec control-plane \
  php artisan cloudtunes:make-admin admin@example.test
```

The command fails if the email does not belong to an existing user. It promotes the account to administrator and approved status. It does not create a password or expose an unauthenticated admin-provisioning endpoint.

For the isolated development stack, use `docker compose -f compose.control-plane.dev.yaml exec control-plane ...` instead.

## Session-based API

These endpoints use Laravel's session authentication and the web middleware. Browser clients must use the normal session cookie and CSRF protection.

- `POST /api/v1/register`: stateless JSON registration endpoint, controlled by the same public-registration flag. Accepts `name`, `email`, `password`, and `password_confirmation`. New accounts are pending approval.
- `POST /api/v1/login`: accepts `email` and `password`; returns the user's approval state and regenerates the session on success.
- `POST /api/v1/logout`: ends the current session.
- `PATCH /api/v1/admin/users/{user}/approval`: administrator-only; accepts `approval_status=approved` or `rejected`.
- `GET /api/v1/stations`: lists the current user's stations.
- `POST /api/v1/stations`: approved users and administrators can create a stopped, draft station by name. Slugs and mount paths are generated by the server.

Station creation does not start an audio process or claim that a stream is playable. Real runtime integration, media upload/quota accounting, and concurrent-running-station enforcement remain subsequent milestones. The station quota is a concurrency limit and must be enforced when a station is started, not merely when a stopped station record is created.
